# PPVIO 手机播放与无名片库

用户已要求把调研后的六项功能全部规划并实现。沿用 Python/aiohttp、SQLite、React 和原生 video；不更换框架，不引入播放器依赖。91 是主要交互参考，Foldergram/Stash 仅参考状态规则与视觉定位方式。

## 范围与方案

1. 精准拖动：短、长视频共用进度控件，目标时间即时反馈，拖动时限频 seek（80ms），松手精确提交。支持键盘；取消/切源不提交过期操作，保留原暂停状态。横滑 seek 复用方向判定，不妨碍短视频上下翻页。
2. 返回保位：应用内返回先关最上层菜单，再关播放器，再回前一页面；接入浏览器 history。刷流/收藏保存列表、当前条目、滚动和筛选状态，隐藏时不保留播放中的 video；片库现有保位继续使用。仅保存浏览状态，不保存凭据或媒体缓存。
3. 失败恢复：同源有界诊断区分登录失效、无权限/源失效、限流、网络和解码问题。仅瞬时网络问题自动重试两次（1s、3s）；保留当前时间与暂停状态，滑走/后台/锁定/切源即取消。提供手动重试与可用时的兼容副本入口。浏览器禁止自动播放时提示点击播放。
4. 画面预览：进度条和片库明确预览操作使用按需生成的 8 张 JPEG（宽320），按时间点显示对应画面。一个生成任务并发、队列最多8项，每项读入上限64MiB，缓存128MiB、7天TTL、预留1GiB磁盘；前台拉流时暂停生成，失败不影响播放。复用现有 loopback SourceServer/读取器，不给 ffmpeg 真实云盘凭据，不上传/删除远端文件。进度预览资源在首次请求前可为空，显示生成状态并降级时间提示。
5. 片内书签：视频ID+时间点+可选名称（最多40字）；播放器添加、跳转、删除，片库“片段”列表可找到所有书签并打开对应时点。全局最多5000条、每片最多200条，相同视频/0.1秒位置幂等。SQLite增加0021迁移；加密恢复快照保存书签，兼容旧版本；视频删除联动清理，扫描暂时下线不删除书签。
6. 片库筛选：最新、时长、大小、随机排序；只看未看、时长区间（全部/1分钟内/1–5分钟/5分钟以上）；随机分页同一查询固定seed。复用后端过滤器，切筛选重置分页且忽略旧请求；加载失败提供重试。

备选方式：更换整套播放器会增加集成与移动端兼容工作；全库预生成会放大网盘流量和缓存。因此选择复用现有功能、按需生成和有界任务。所有默认值是本轮实现选择；用户已授权完整构建，不再增加设计确认流程。

## 数据与边界

- 新迁移只新增，不改历史文件；先在SQLite backup API生成的生产副本演练并检查原有表/行数。回滚使用发布脚本的数据库快照与旧镜像。
- 认证、同源写入、opaque ID、当前副本选择和存量加密格式保持；书签快照仅增加兼容字段/版本，不改变加密上下文。
- 只操作PPVIO，禁止访问TGVIO代码、数据库和凭据。测试使用合成媒体/fake/loopback，无生产Cookie和媒体。
- 新前端模块不超过600行，后端不超过1000行；不新增依赖。
- 最终全量检查、独立代码审查、合成媒体浏览器验收；不宣称做过实体手机验收。依照既有授权在通过后推送main，用release.py上线，只更新ppvio容器。

## 验收重点

快速翻页/切源/锁定不留下旧重试、seek或预览；返回恢复不触发隐藏播放；随机分页不重复；书签持久化/恢复/删除；预览缓存与任务有界且失败不影响主播放；已有加载提示和弱网预载回归通过。
