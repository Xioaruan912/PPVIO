# 标签收藏与片库体验

本轮将整片收藏入口替换为快捷标签收藏，保留片内书签。片库提供观看历史、自选封面、保存筛选频道、片段标签、混合待播队列、标签别名/父级/合并，以及精品标记。

## 存储行为

给视频打标签后，唯一后台 worker 使用 WebDAV MOVE 将原文件归类到库根的 `标签收藏/<标签名>--<ID>/`。第一个标签是主标签，其他标签只作检索；移除主标签选择剩余标签，移除最后标签返回原位置。标签改名/合并不重命名已存放目录。文件名冲突使用稳定后缀，始终 `Overwrite: F`；有源 ETag 时发送 `If-Match`。

0024 保存原路径、当前路径和未确认 MOVE 计划。取消或网络失败不得丢计划；重试先查源/目标并验证大小。更换存储端点会阻止旧计划继续执行。删除视频与 MOVE 互斥；未开始的归类可暂停以便删除，撤销删除会恢复归类。扫描普通目录时把归类文件映射回原 media_id，归档原清单仍保持不可变。

v5 加密恢复快照包含标签、频道、片段标签、精品、自选封面和归类状态，兼容 v1–4。恢复不会自动批量移动原文件。观看历史只在本地服务器保存，可关闭/清空；临时队列只在当前浏览器保存。

## 旧组迁移顺序

1. 保持旧 `CollectionBackupService` 和 favorite sync 轮询停用，禁止其递归删除旧组目录。
2. `POST /api/v1/tag-collections/import-legacy {}` 原子导入手工组同名标签，保留旧组/副本。重复调用安全。
3. 先单条试迁移，再 `POST /api/v1/tag-filing/organize` 排队现有有效标签视频。只有主 worker 执行 MOVE。
4. 等待 synced，逐项核实远端大小、播放器 Range，并全量扫描确认原 ID/标签仍有效。对于迁移前即已缺失的旧成员，仅在导入标签已保留、所有已知源路径确认为缺失、无副本可清理时，操作员可移除旧组关系；不删除媒体记录或标签关联。
5. `POST /api/v1/tag-collections/retire-legacy {"cleanup_limit":1000}` 再次核实全部有效成员后删除旧手工组。仅有持久授权标记的旧副本可逐文件清理，遇到失败保留重试行。不会递归删除目录或整个收藏根。
6. 等待 v5 备份 dirty revision 被后台 exporter 确认，核实远端最新快照无旧手工组并有全部归类状态。

所有维护输出仅含计数和固定错误码。生产凭据和媒体不写日志/截图。浏览器验收使用本地合成视频，不代替实体手机验收。

## 回滚

发布脚本保存升级前 SQLite backup、环境和旧镜像。开始物理 MOVE 后，不能只恢复旧数据库：先保留当前0024状态及最新 v5 快照，使用已确认的当前位置把文件逐项迁回原路径（不覆盖、核实大小），再考虑切回旧版。若只回滚界面，保留兼容新路径的后端与归类数据库。
