# PPVIO 用户片库体验

用户已选定并要求实施上一轮表格全部七项：观看历史、手选封面、保存筛选频道、片段标签、临时播放队列、标签层级/别名/合并、普通/精品分级。沿用React/native video/SQLite/aiohttp，不增加依赖，不识别/上传用户媒体，按后续用户指令，将标签收藏的原视频通过 WebDAV MOVE 归类。

## 用户行为

1. 历史：实际前台播放累计至少2秒才记录，15秒节流及退出播放器保存；每视频保留最近一次记录和位置，最多2000条。片库按日期显示封面，点击原视频并跳到保存位置。全局记录开关默认开；单条/全部删除、开关变更增加epoch，迟到的旧写入不得恢复已清除记录。历史是服务器本地可清空浏览记录，不进入云端恢复快照。
2. 手选封面：播放器“更多”里选当前画面或现有8帧预览；同源canvas缩放JPEG后上传，浏览器跨源/解码失败需说明且可选预览重试。保持默认封面可恢复。每图64KiB，总16MiB，尺寸有界；JPEG原字节持久化SQLite且进入加密备份；选择/清除后列表封面更新。
3. 频道：最多30个命名筛选。条件为include_tags/exclude_tags、all/any、watched(all/unwatched/watched)、min_seconds/max_seconds、category(all/short/long)、premium_only及sort(newest/longest/largest/random)。每组最多20个标签，排除优先。动态查询当前有效主视频，新片自动加入；可创建/编辑/删除、进入频道浏览并播放。内置“精品”浏览入口复用同一查询。
4. 片段标签：每书签最多20个现有标签，书签备注可直接编辑；片段墙及连刷支持按片段标签筛选。真实media_id/独立clip key、真实时长范围约束和弱网预载保持。
5. 临时队列：浏览卡片/播放器可加入，本浏览器最多100个不同视频，支持查看/移除/清空/调整顺序、上条/下条/随机和播放结束继续；混合短片和长片，分别复用原播放器。过期/已删除视频反馈并可跳过；关闭重开保留队列，不改变收藏或合集。
6. 标签管理：改名、删除、别名、单父级分组及合并；名称与别名遵循既有SQLite ASCII NOCASE，不得互相冲突，最多10个别名/标签。父级无环、深度最多8。合并原子迁移视频/待扫描绑定、片段标签、偏好和频道引用；排除优先；子节点重挂且不得制造环。旧单标签API与已有数据兼容。
7. 精品：每视频可切换普通/精品，独立于收藏；播放器有直接操作，片库有“精品”入口，频道支持只看精品。

## 数据及交付

只新增0023、0024迁移，既有迁移校验和不变。manifest升v5兼容1–4，加密上下文不变；新增频道/精品/片段标签/标签详情/自选封面进快照，历史和浏览器临时队列不进云端备份。完整恢复仍原子；按名称映射标签，处理书签位置冲突的ID映射，不丢未扫描媒体状态。快照读写上限64MiB，封面总16MiB；上传前拒绝超限，保留旧远端指针。

只操作PPVIO，保留认证、同源和opaque ID；不读TGVIO运行数据。实现后完整检查、独立审查、合成媒体手机视口浏览器验收、生产库副本迁移22→24，然后推送main并release.py发布，核对其他容器不变并保留旧数据库/镜像回滚。实体手机仍按此前要求暂缓。

## 已确认的标签收藏变更

用户指定以标签取代旧收藏/手工分组；快捷选择展示最近和常用标签，片库以标签浏览收藏。打标签后移动原视频到其主标签目录，其他标签只作检索；删除最后标签返回原位置。目录为库根/标签收藏/标签名--ID，冲突使用稳定后缀，MOVE 从不覆盖。源 ETag、持久计划和目标 stat 保证可重试；扫描及 v5 恢复保留原 media_id 和元数据。旧备份 worker 不再启动。

本次已授权整理现有数据并上线：先把旧手工组转为同名标签（保留关联），排队移动现有视频，验证文件存在/大小、播放范围和重扫身份，然后删除旧分组。仅逐文件清理有授权标记且已核实的旧组副本；不删除整个收藏备份根或恢复配置。保留升级前数据库及旧镜像；回滚涉及文件位置时须先按当前已确认路径回迁，不能直接丢弃新归类状态。
