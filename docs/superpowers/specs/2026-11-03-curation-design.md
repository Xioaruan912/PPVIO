# PPVIO 偏好刷流、整理与片段循环

用户要求按上一轮优先推荐实施：偏好标签刷流、待整理队列与批量打标、收藏片段连刷。继续使用现有原生video、React、SQLite和读取/发布流程，不增加依赖或外部识别服务。

## 功能与边界

1. 刷流偏好：保存最多20个偏好标签、20个排除标签，以及mixed/only模式；排除优先。mixed按3条偏好、1条其他内容的规则混排，来源不足时回退；保留未看优先与近期避重。only要求至少一个偏好标签，匹配任意一个即可。变更偏好后旧请求/旧队列不能重新填回；空结果说明筛选条件，允许改偏好。
2. 待整理：看过与整理完成分别保存。片库可打开待整理/已整理列表，最多100个视频一次追加/移除标签或修改整理状态；操作整体校验并原子应用。支持重复使用最近标签组；不改动/搬移媒体文件。当前播放器可标记整理完成并进入下一条。
3. 片段：书签可选择结束点；旧时间点书签保持兼容，连刷时默认20秒，受真实视频时长约束。片段列表可打开范围循环的上下刷流；一个源里的多个片段有不同视图key。继续复用最多三个video和原有缓冲授权，当前片段未就绪不得抢预载。暂停/锁定/后台/失活/切源须取消旧跳转和循环；拖动限于片段范围。无需生成新视频文件。

## 数据与恢复

- 新增0022迁移：书签end_ticks可空；player_media_curation保存organized/updated_at；player_feed_preferences保存偏好、排除、mode；player_pending_media_tags用于恢复后尚未扫描的媒体标签。
- 偏好和整理状态属于本私人片库的全局状态，与现有全局标签/看过/书签一致；当前浏览器最近标签组只保存有限ID列表。
- 加密manifest升至v4，读取v1–v3；包含完整标签定义/标签关联（含待扫描关联）、整理状态和偏好；bookmarks包含可选end_seconds。标签ID冲突按名称合并并映射，不丢弃未扫描媒体的数据。
- 复用现有持久化dirty revision和有锁快照导出。标签/关联、偏好、整理状态及书签区间变化均触发备份；旧备份缺少新字段时不得清空本地新状态。验证新数据后才恢复，不改加密上下文。
- 偏好/标签关联变化删除未消费的旧feed队列；不清除看过历史。新队列仍是每周期无重复，近期避重为小片库尽力策略。
- 只操作PPVIO；opaque ID、认证、同源、1000行后端/600行新前端模块上限保持。测试全离线，迁移用SQLite backup API生产副本演练，发布保留可用回滚快照。

## 验收

偏好/排除生效、仅偏好为空、稀疏标签、批量无半成功、整理状态与看过独立；v1–v4恢复兼容、未扫描标签恢复与并发导出；同源多个片段独立、默认20s/显式结束点、拖条与横滑不越界、真实duration变化/锁定/后台不串状态。完整检查、独立审查和合成媒体手机视口浏览器验收后推送main并release.py上线；实体手机验收仍按用户此前要求暂缓。
